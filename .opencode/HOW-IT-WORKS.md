# HireIQ Multi-Agent Orchestration System — How It Works

## 1. What Is This?

This is a **production-grade multi-agent system** built on top of opencode. It turns opencode from a simple AI coding assistant into a **team of specialized AI agents** that work together on your project. Each agent has a specific role, its own knowledge (skills), and its own memory of the project.

Think of it like hiring a team of expert developers:
- A **React specialist** for frontend work
- A **Python architect** for the backend
- A **security auditor** to keep things safe
- A **UX designer** for responsiveness and accessibility
- A **code reviewer** to enforce quality standards
- A **performance engineer** to keep the app fast

### Step-by-Step Flow

**Step 1: You give a prompt to opencode**

Example: _"Add a dark mode toggle to the navbar"_

**Step 2: opencode reads `agents/agents.json`**

This tells opencode:
- Which agents exist (`frontend`, `backend`, `security`, etc.)
- Which agents can run **in parallel** (most of them)
- Which agent runs **sequentially** (codeReview — the quality gate)
- Which **skills** each agent should load
- Which **memory files** to read for project context

**Step 3: opencode loads the project memory**

Instead of scanning every file in your project (which costs tokens), opencode reads pre-compiled `.md` files from `.opencode/memory/`:

| File | What It Contains | How It's Created |
|------|------------------|------------------|
| `project-context.md` | Overview, tech stack, key decisions | You write this once |
| `frontend-structure.md` | All frontend files with line counts | Auto-generated by PowerShell script |
| `backend-structure.md` | All backend files with line counts | Auto-generated by PowerShell script |
| `dependencies.md` | All npm and pip packages | Auto-generated by PowerShell script |
| `decisions.md` | Architecture Decision Records (ADRs) | You write this as decisions are made |
| `changelog.md` | What changed and when | You maintain this (or auto-generate) |

**This is the key efficiency trick**: Instead of opencode reading 60+ source files to understand the project structure, it reads 6 small `.md` files. This reduces token usage by **5-10x**.

**Step 4: opencode routes to the right agent(s)**

Based on your prompt, opencode determines which agents to activate:

| If your prompt mentions... | Agent(s) activated |
|---------------------------|-------------------|
| React, component, UI, frontend, hook, context | `frontend` + `responsiveUX` + `accessibility` + `performance` |
| Python, API, endpoint, backend, database | `backend` + `security` |
| Security, auth, XSS, CORS, vulnerability | `security` |
| Responsive, mobile, tablet, device, touch | `responsiveUX` |
| Accessibility, a11y, screen reader, keyboard | `accessibility` |
| Performance, bundle size, slow, optimize | `performance` |
| Docker, deploy, CI/CD, infrastructure | `devops` |

**Step 5: Agents load their skills**

Each agent loads domain-specific knowledge from `.opencode/skills/`:

```
FrontendAgent loads:
  ├── skills/frontend/react-optimization.md   (memoization, type rules, patterns)
  └── skills/shared/responsive-design.md       (breakpoints, touch targets)
  └── skills/shared/accessibility.md           (WCAG, ARIA, keyboard nav)

BackendAgent loads:
  ├── skills/backend/python-best-practices.md  (async, type hints, structures)
  ├── skills/backend/api-security.md           (validation, auth, headers)
  └── skills/backend/performance.md            (pooling, caching, parallel)

CodeReviewAgent loads:
  ├── skills/shared/code-review.md             (checklist of 40+ checks)
  └── skills/shared/solid-principles.md        (SRP, OCP, ISP, DIP enforcement)
```

**Step 6: Agents execute (parallel where possible)**

- `frontend`, `backend`, `security`, `responsiveUX`, `accessibility`, `performance`, `devops` — all run **in parallel**
- `codeReview` runs **after** all others finish (it's the quality gate)

**Step 7: CodeReviewAgent validates everything**

Before changes are finalized, CodeReviewAgent checks:
- No `any` types used
- All API calls have error handling
- No hardcoded secrets
- SOLID principles followed
- Build passes with zero errors

**Step 8: Memory auto-updates**

After every change, the memory update script runs automatically:
- Scans `frontend/src/` for new/deleted files
- Scans `backend/` for new/deleted Python files
- Updates `frontend-structure.md` and `backend-structure.md`
- Updates `dependencies.md` with current package versions

This happens on **every `git commit`** (via pre-commit hook), so your memory is always fresh.

## 3. How to Use It

### Everyday Development

Just use opencode normally. The agent system works automatically in the background.

```bash
# Example prompts that trigger specific agents:
opencode "Add a new page for interview history"        → FrontendAgent
opencode "Create a DELETE endpoint for sessions"        → BackendAgent
opencode "Fix the CORS configuration for production"    → SecurityAgent
opencode "Make the navbar work on mobile"                → ResponsiveUXAgent
opencode "Add keyboard shortcuts to the interview room"  → AccessibilityAgent
opencode "Why is the bundle so large?"                   → PerformanceAgent
```

### Running the Memory Update Manually

```powershell
# Windows
powershell -ExecutionPolicy Bypass -File .opencode/scripts/update-project-memory.ps1

# This updates frontend-structure.md, backend-structure.md, and dependencies.md
# with the current state of your project.
```

The script also runs automatically on `git commit` (via pre-commit hook).

### Adding a New Agent

1. Add the agent definition to `.opencode/agents.md`
2. Add its config to `.opencode/agents/agents.json`
3. Create its skills in `.opencode/skills/<domain>/`
4. Create its prompt in `.opencode/prompts/agents/`

### Adding a New Skill

Create a `.md` file in the appropriate skills directory:

```
.opencode/skills/frontend/     → React/TypeScript skills
.opencode/skills/backend/      → Python/FastAPI skills
.opencode/skills/shared/       → Cross-cutting skills (security, a11y, etc.)
```

Then reference it in the agent's config in `agents.json`.

### Recording an Architecture Decision

Edit `.opencode/memory/decisions.md` and add a new ADR entry:

```markdown
## ADR-008: Add PostgreSQL Database
**Status**: Proposed  
**Date**: 2026-05-18  
**Decision**: Replace in-memory TTLCache with PostgreSQL  
**Rationale**: Sessions need persistence across restarts
**Consequences**: Need to add SQLAlchemy, migration system
```

## 4. Key Concepts Explained

### What Is "Agent Memory"?

Agent memory is the set of `.md` files in `.opencode/memory/`. These files act as the agents' "knowledge base" about the project. Instead of reading every source file, agents read these compact summaries.

**Why this matters**: Reading 60 source files costs ~15,000 tokens. Reading 6 memory files costs ~1,500 tokens. That's **10x less tokens** for the same context.

| Approach | Tokens per query | Speed |
|----------|-----------------|-------|
| Scan every file | ~15,000 | Slow |
| Read memory files | ~1,500 | Fast |

### What Are "Skills"?

Skills are Markdown files that teach an agent how to work in a specific domain. Each skill contains:
- **Rules**: "Never use `any` type"
- **Patterns**: "Use `build_system_message()` instead of inline construction"
- **Checklists**: "Test on 320px width, test with keyboard only"
- **Code examples**: Specific patterns to follow or avoid

Skills are loaded by the agent when it's activated, giving it domain-specific expertise.

### Why Parallel vs Sequential?

| Execution | Agents | Why |
|-----------|--------|-----|
| **Parallel** | Frontend, Backend, Security, ResponsiveUX, Accessibility, Performance, DevOps | They work on different files and concerns; no conflicts |
| **Sequential** | CodeReview | Must see ALL changes before validating; it's the quality gate |

### What Is the Quality Gate?

The CodeReviewAgent is the **last step** before changes are finalized. It enforces:
1. **Type safety**: No `any`, all interfaces explicit
2. **Error handling**: Every API call wrapped in try/catch
3. **SOLID principles**: Single Responsibility, Open/Closed, Liskov, Interface Segregation, Dependency Inversion
4. **Security**: No secrets leaked, inputs validated
5. **Performance**: No unnecessary re-renders, bundle considered
6. **Build**: `npm run build` must pass with zero errors

If CodeReviewAgent rejects the changes, you get specific instructions on what to fix.

## 6. Common Workflows

### "I want to add a new feature"
1. Tell opencode what you want (e.g., "Add a page to view past interview transcripts")
2. FrontendAgent creates the new component/page
3. BackendAgent creates the API endpoint if needed
4. SecurityAgent reviews for vulnerabilities
5. ResponsiveUXAgent ensures mobile compatibility
6. AccessibilityAgent adds ARIA labels and keyboard nav
7. PerformanceAgent adds code splitting if needed
8. CodeReviewAgent validates everything
9. Memory auto-updates with new file structure
10. Build runs to confirm zero errors

### "I want to understand the project"
Read these files in order:
1. `.opencode/memory/project-context.md` — What is this project?
2. `.opencode/memory/frontend-structure.md` — What frontend files exist?
3. `.opencode/memory/backend-structure.md` — What backend files exist?
4. `.opencode/memory/decisions.md` — Why were key decisions made?
5. `.opencode/agents.md` — What agents are available?

### "I want to optimize performance"
The PerformanceAgent will:
1. Analyze bundle size (426 KB gzipped — target <300 KB)
2. Check for unnecessary dependencies
3. Recommend code splitting at route level
4. Suggest replacing heavy libraries (e.g., `html2pdf.js` → `jspdf` + `html2canvas`)
5. Review memoization and re-render patterns

## 7. Troubleshooting

### Memory files are outdated
Run the update script manually:
```powershell
powershell -ExecutionPolicy Bypass -File .opencode/scripts/update-project-memory.ps1
```

### An agent is not responding correctly
Check its prompt in `.opencode/prompts/agents/` and its skills in `.opencode/skills/`. The agent's behavior is defined entirely by these files.

### CodeReviewAgent is rejecting valid code
The review rules are in `.opencode/skills/shared/code-review.md` and `.opencode/skills/shared/solid-principles.md`. You can adjust the thresholds there.

### Build fails after agent changes
Check the opencode output for specific errors. The CodeReviewAgent should catch these before they reach the build step, but if it doesn't, check `skills/shared/code-review.md` for the missing check.
